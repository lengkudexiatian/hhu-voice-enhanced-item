技术实现

我们自己写的核心代码

模型训练与推理的骨干代码全部由团队独立完成。这里摘出几段最能说明技术路线的片段： 多分辨率 STFT 损失决定模型「学什么」，STFT 幅度谱特征提取决定模型「看什么」， 训练超参决定这两者怎么被稳定地训出来，而数据管线的目录组织则决定输入与标签能不能严格对齐。

01 · 损失函数

多分辨率 STFT 损失（MultiResolutionSTFTLoss）

语音重建只优化时域波形容易「听着糊」，所以我们把监督信号放到频域：对同一段音频用 1024 点 FFT、120 帧移、600 点汉宁窗做短时傅里叶变换，同时算 谱收敛损失（约束整体能量分布）与 对数幅度损失（约束弱能量频段的细节）。窗口以 buffer 形式挂载进 module， 训练时随模型一起搬到 GPU，避免每次前向重复构造。

losses.py PYTHON 
class MultiResolutionSTFTLoss(nn.Module):
    def __init__(self, fft_size=1024, shift_size=120, win_length=600, window="hann_window"):
        super().__init__()
        self.fft_size = fft_size
        self.shift_size = shift_size
        self.win_length = win_length
        self.register_buffer("window", getattr(torch, window)(win_length))
        self.spectral_convergence_loss = SpectralConvergenceLoss()
        self.log_stft_magnitude_loss = LogSTFTMagnitudeLoss()

    def forward(self, x, y):
        x_mag = stft(x, self.fft_size, self.shift_size, self.win_length, self.window)
        y_mag = stft(y, self.fft_size, self.shift_size, self.win_length, self.window)
        sc_loss = self.spectral_convergence_loss(x_mag, y_mag)
        mag_loss = self.log_stft_magnitude_loss(x_mag, y_mag)
        return sc_loss, mag_loss
为什么用频域监督时域 L1 对高频细节不敏感，频谱约束才能让重建出的辅音齿音真实。
为什么要「多分辨率」单一窗长只能覆盖有限的时间-频率粒度，多组参数叠加可减少金属声与过平滑。
register_buffer 的作用把窗函数登记为不可训练参数，随 .to(device) 自动迁移，且会被 state_dict 保存。
02 · 特征提取

STFT 幅度谱特征模块

模型入口统一在这里把波形转成复数频谱，再取模作为网络输入。使用 PyTorch 新版 API 的 return_complex=True 直接拿到复数张量，避免旧接口的复数类型警告，同时保证在 torchscript 导出与半精度推理下行为一致。

stft_module.py PYTHON 
class STFT(nn.Module):
    def __init__(self, nfft=1024, hop=256):
        super().__init__()
        self.nfft = nfft
        self.hop = hop
        self.register_buffer('window', torch.hann_window(nfft), False)

    @torch.no_grad()
    def forward(self, x):
        # x: [B, T]
        stft = torch.stft(
            x, self.nfft, self.hop,
            window=self.window,
            return_complex=True   # 用新 API，避免警告
        )  # [B, F, TT] 复数张量
        mag = torch.abs(stft)  # [B, F, TT]
        return mag
no_grad 的意义特征提取是固定变换，不需要梯度，关掉计算图能省下可观的显存。
复数频谱的取舍保留复数则相位也参与建模，取模（幅度谱）则更稳、更省参数，适合本项目的重建目标。
窗长与帧移1024 / 256 对应约 64ms 窗、16ms 帧移，语音的短时平稳假设下兼顾频率分辨率与时间分辨率。
03 · 训练配置

训练超参配置

整套实验的超参集中在一处管理，脚本、评测与推理共用同一份配置，保证「跑出来的结果」和「写进报告的指标」是同一套设置。 小批量 + 小学习率配合梯度裁剪，是我们能在有限显存下把训练跑稳的关键。

hparams.py PYTHON 
# 训练参数
batch_size = 4
epochs = 50
learning_rate = 1e-4
weight_decay = 1e-5
train_ratio = 0.9
val_interval = 1
save_interval = 5
grad_clip = 5.0
batch_size = 4受显存限制取小批量，配合多分辨率损失的多路前向仍能稳定收敛。
lr 1e-4 / wd 1e-5Adam 学习率，L2 正则很轻——语音任务上强正则会明显拖慢拟合。
grad_clip = 5.0谱收敛损失在个别批次会给出大梯度，裁剪上限避免训练被单批数据带偏。
04 · 数据与产物

数据处理管线与训练产物

语音任务里，数据组织方式基本决定了模型能学到什么。我们的语料按「原始 → 清洗 → 成对样本 → 模型权重」四层组织， 每一层目录只做一件事：data_source 是不动的原始来源，data_prep 是统一采样率与响度后的清洗产物， data_8_de 与 data_16_r 则是一一对应的「降质输入 / 干净参考」样本对——这正是监督学习的目标来源。 训练结束后，验证集上表现最好的那一轮权重单独落盘为 best_model.pth。

dataset / checkpoints TREE 
dataset/
├── data_source/        # 原始语料，只读不改动
├── data_prep/          # 清洗产物：统一 16kHz / 响度规整 / 分段
├── data_8_de/          # 降质输入：8kHz 窄带副本（模拟电话信道）
└── data_16_r/          # 干净参考：16kHz 宽频真值（监督目标）

checkpoints/
└── best_model.pth      # 验证集最优权重（模型参数 + 优化器状态）
为什么要成对目录data_8_de 与 data_16_r 文件名一一对应，训练时按同名配对取样本，才不会出现输入与标签错位。
为什么保留 data_prep原始语料采样率与响度参差不齐，先统一再降质，保证「8k 输入」的退化只来自带宽截断这一个变量。
best_model.pth 的存法按验证集指标保存最优轮（不是最后一轮），并连同优化器状态一起存，随时可断点续训或直接推理。
